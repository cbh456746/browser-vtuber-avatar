# 공개 준비 검증 기록

기준일: 2026-10-18. 이 문서는 실제 실행한 검사와 별도 확인이 필요한 항목을 구분합니다.

## 검사 대상

버전 0.2.3의 Windows 데스크톱 앱, 캐릭터팩 입력·에이전트 워크플로우·공개 파일·배포 후보를 대상으로 합니다. 개인용 캐릭터 원본과 프레임은 공개 소스에서 제외합니다.

위 결과는 전문 외부 침투 테스트 인증이 아닙니다. 공격 시나리오는 [위협 모델](THREAT_MODEL.md)에 연결합니다. 모의 서버는 이 테스트가 만든 로컬 서버이며 실제 사용자 계정이나 외부 서비스를 공격하지 않습니다.

검사 명령은 npm test, test:desktop, avatar:check, audit:public, npm audit, package:win, verify:release입니다. 로컬 런타임은 Electron 44.9.0을 사용했습니다. 로컬 소켓 통신을 제한하는 실행 환경에서는 모의 서버 검사가 타임아웃될 수 있으므로 실제 코드 실패와 환경 제한을 구분합니다.

첫 공개 커밋 `83b76aedecdd3a8bc4d224ae399dee68b6f9a096`은 별도의 깨끗한 Linux·Windows 환경에서 [GitHub CI가 성공](https://github.com/cbh456746/browser-vtuber-avatar/actions/runs/39092239319)했습니다. Linux 검사와 Windows 데스크톱·실행파일 검사가 모두 통과했습니다. 후속 변경은 해당 커밋의 Actions 결과를 다시 확인합니다.

## 실제 VTS 연결 오류와 0.2.2 수정

VTS 1.35.10에서 기본 내장 WebSocket으로 인증 토큰을 받은 뒤 빈 응답이 들어오고 인증이 완료되지 않는 현상을 재현했습니다. 이전 구현은 빈 메시지를 JSON 오류로 처리하고 재접속 때 승인 요청 제한까지 초기화했습니다. ws 8.22.0으로 같은 공식 API 요청을 보내 인증과 5개 파라미터 수신이 정상 동작하는 것을 확인했습니다. 전송 계층 내부의 정확한 실패 기전까지 규명했다는 뜻은 아닙니다.

0.2.2는 호환성을 확인한 통신 구현을 포함하고, 빈 메시지의 안전한 처리·인증 전후 단절 시 토큰 재사용·승인 대기 중 단절 시 중단·추적 API 권한 철회 처리를 보강합니다. 실제 VTS에서 OS 암호화 토큰 저장 후 앱 UI로 재접속했습니다. 추가 승인 요청 0회로 응답 1,000개를 수신했습니다.

첫 진단 당시 VTS의 FaceFoundResponse는 false였고 포즈 값의 변화는 없었습니다. API 인증·추적 데이터 수신과 실제 얼굴 감지를 구분하여, 앱에 카메라·휴대폰 추적 확인 안내를 표시합니다. 이후 실제 추적을 켠 상태에서 앱 UI로 재접속해 100회 관측 중 94회의 포즈 변화를 확인했고 캐릭터 표시도 유지됐습니다. 얼굴 영상·추적 수치·토큰은 보고서에 기록하지 않습니다. 추적 지연·정확도·모든 방향과 표정·모든 입력 장치에 대한 종합 검증 완료로 확대 해석하지 않습니다.

관련 공식 규격: [인증과 토큰 재사용](https://github.com/DenchiSoft/VTubeStudio#authentication), [얼굴 감지 여부 확인](https://github.com/DenchiSoft/VTubeStudio#checking-if-face-is-currently-found-by-tracker).

## 닫힌 입선과 영구 고개 감도: 0.2.3

개인 캐릭터 A·D의 원본 프레임을 확인해, 입을 닫은 상태의 그림 자체에서 입선이 누락된 것을 발견했습니다. 두 시트를 이미지 생성 도구로 보정한 후 50프레임을 새 캐릭터팩으로 만들었습니다. 기존 캐릭터팩은 보존하고 나머지 B·C·E·F의 100프레임은 바이트 단위로 동일함을 확인했습니다. 보정 팩은 총 150개의 고유 프레임과 투명 여백·경계·메타데이터 검사를 통과했습니다. 실제 Electron 설정 창과 방송 창에서 150개 상태·눈 감기·입 전환·반전·배경 변경을 검사했습니다.

A·D 총 50개를 128·256px 크기의 밝은 배경과 어두운 배경에서 직접 시각 검수했습니다. 향후 생성 프롬프트에 닫힌 입선을 명시하고 `avatar:check`가 50개 이미지의 SHA-256에 연결된 두 표시 크기의 검수 기록을 요구합니다. 기록 누락·미검수·이미지 변경·중복 기록은 회귀 테스트로 차단합니다. 이 기능은 입을 의미적으로 자동 인식하는 검출기가 아니며, 실제 그림의 시각 검수를 대신하지 않습니다. 기록을 사실과 다르게 작성하면 누락을 방지할 수 없습니다.

고개 좌우·상하 추적 입력은 범위 제한 전 0.85배로 조정했습니다. 기본값은 소스에 고정되어 재실행·새 캐릭터·새 설치에도 유지됩니다. 0°·±15°·±30°·±90° 응답으로 15% 감소와 범위 제한을 검사했고 눈·입 값은 그대로임을 확인했습니다. 프레임 선택은 5단계이므로 눈에 보이는 이동량이 매 순간 연속적으로 15% 줄어드는 것은 아닙니다. 이번 감도 변경의 검증은 모의 VTS 응답과 실제 앱 렌더링을 사용하며, 위 절의 실제 장치 연결 결과와 구분합니다.

새 실행파일은 버전별 폴더에 빌드해 사용 중인 이전 버전을 덮어쓰지 않습니다. 이미 불러온 개인 캐릭터팩이 자동 수정되는 것은 아니므로 앱에서 보정된 팩을 선택해야 합니다. 개인 에셋과 검수 원본은 공개 저장소에 포함하지 않습니다.

## 일러스트 제작·실제 장치·방송과 구분

2026-10-18에는 추가로 제공된 비공개 일러스트 한 장에서 내장 image_gen 도구로 6개 표정 시트를 실제 생성했습니다. 1254×1254 생성 시트의 불균등한 행 간격은 공통 투명 경계·배율·기준점을 이용해 비공개 사전 처리한 뒤 150개의 512×512 PNG로 분리했습니다. 출력 크기가 원래 그림의 세부 해상도를 증명하지는 않습니다.

150개 모두 고유한 픽셀이며 투명 여백·경계·메타데이터 검사를 통과했습니다. 실제 Electron 설정 창과 방송 창에서 150개 상태를 모두 로드하고, 수동 조작·좌우 반전·초록/자홍 배경을 검사했습니다. 생성 시트·캐릭터팩·미리보기·프롬프트 원문은 비공개로 보관합니다. 방향 각도는 생성 프롬프트의 목표이며 물리적으로 정밀 보정한 추적 각도는 아닙니다.

이 시험에서 빠른 연속 조작의 마지막 입 모양이 누락되는 문제를 발견했습니다. 0.2.1은 20ms 갱신 제한을 유지하면서 마지막 입력을 예약 반영하고, 모드를 전환하면 예약 입력을 취소합니다. 마지막 상태 보존과 모드 전환 회귀 검사를 추가했습니다.

- CI와 자동 회귀 시험은 모의 API를 사용합니다. 별도의 실제 VTS 연결 시험 결과는 위 절과 구분합니다. iPhone부터 아바타 동작까지의 종합 시험은 아직 완료하지 않았습니다.
- 마이크의 네이티브 동의·권한 정책과 종료 코드는 검토하지만 실제 마이크 신호와 발화는 별도 사용자 시험이 필요합니다.
- OBS에서 실제 장면·녹화·알파·크로마키·오디오가 정상인지 별도 확인해야 합니다.
- 입력 그림마다 생성 품질이 다르므로 새 캐릭터를 만들 때마다 150프레임을 검수합니다. 이번 시험의 성공이 다른 일러스트의 품질이나 자동 제작 성공을 보장하지 않습니다.
- 장시간 부하·모든 디코더 취약점·모든 프롬프트 인젝션·관리자 권한 악성코드를 방어했다고 주장하지 않습니다.

## 배포 상태

소스 공개가 승인된 범위입니다. 실행파일은 로컬 검증용이며 공개 Release에 올리지 않습니다. 코드 서명 인증서가 없어 미서명입니다. 정식 바이너리 배포 전 서명·배포자·무결성·사용자 동작 검증 정책을 확정해야 합니다.

원시 로그·토큰·원본 이미지·개인 캐릭터팩은 이 보고서에 첨부하지 않습니다. 로컬 검증 결과와 SHA-256 정보는 release 폴더에 보관하고 Git에서 제외합니다.
